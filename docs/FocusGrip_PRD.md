# FocusGrip · 产品需求文档（PRD）

**副标题**：面向 ADHD 攀岩爱好者的握力控制小游戏 · AdventureX 2026 Game Jam
**版本**：v1.0（Jam MVP 版）
**日期**：2026-07-23
**开发窗口**：约 2.5 天（软件 + 硬件并行，含联调）

---

## 0. 本版关键决策（先记账，避免跑偏）

- **主玩法**：方案一「握力驱动攀岩」为核心；方案二「节奏」降级为可选高难模式，属加分项，做不完不影响主线。
- **砍掉摄像头走神检测**：MVP 不做 AI 姿态识别。核心链路只保留两条腿——**压力反馈（握力输入）+ 游戏反馈（攀岩输出）**。走神检测列入未来扩展。
- **硬件极简**：单颗力传感器即可跑通全部玩法，尽量降低硬件同学的准备与联调负担。
- **落地形态**：Web 端（浏览器直接演示），用最小成本换最大视觉表现；追求**高完成度 + 好看**，而非功能多。
- **已确认核心机制**：力度窗口抓点 + 持续保持点。

---

## 1. 一句话定位

> 捏握一个带压力传感器的玩具，实时控制一个小人在攀岩线上往上爬。
> 力度刚好=干净抓点上升，力度失控=魔性甩飞。既练攀岩指力，又练"把注意力稳住"。

**目标人群**：ADHD ∩ 攀岩爱好者（两个圈层合一，形成差异化）。
**一句话价值**：把本来就要做的 fidget（捏握）变成一件有反馈、有成就感的事——一次训练指力，一次练习自我调控。

## 2. 设计目标与约束

| 维度 | 目标 |
|---|---|
| 扣题 | 视觉与叙事一眼看懂"这是为攀岩者做的"；评委 3 秒 get |
| 手感 | 握力→动作的因果直给、跟手、有物理反馈 |
| 完成度 | 一条完整可玩关卡 + 结算，能从头玩到尾不卡壳 |
| 视觉 | 手绘卡通风（对齐参考图 6/7），少量美术资产撑满画面 |
| 工作量 | 2.5 天可交付；硬件只依赖 1 颗传感器 |
| 传播点 | 至少 1 个"魔性甩飞"的可截图/录屏瞬间 |

**非目标（本版明确不做）**：摄像头/姿态识别、账号系统、多人、云端数据看板、多关卡大地图、复杂剧情。

## 3. ADHD 主题如何在没有摄像头的情况下依然扣题

砍掉走神检测后，ADHD 的命中点**内化进玩法机制本身**：

- **持续保持点（sloper）** = 直接的"持续注意力"训练：要求把握力稳定在窗口内数秒，一分神/手抖导致力度漂移，进度就回退。这是一个纯粹的**自我调控练习**，比"摄像头抓你走神"更正向、更少被监视感。
- **力度窗口** = 冲动控制训练：ADHD 常见"用力过猛/坐不住"，游戏惩罚过度发力（甩飞），奖励恰到好处的克制。
- **短关卡（60–120 秒）** = 适配易分心的注意力跨度，一次一小段"专注冲刺"，完成即正反馈。

叙事口径：**"游戏本身就是干预"**——你不是被 AI 监视，而是在一个需要专注和分寸感的身体任务里，练习把注意力稳住。

## 4. 核心玩法

### 4.1 基本循环（Core Loop）

```
看到下一个抓点（高亮 + 目标力度环）
        ▼
捏握玩具，握力条上升
        ▼
把力度送进绿色窗口并短暂稳住
        ▼
小人发力 → 干净抓住 → 身体上移
        ▼
（重复，直到）够到 TOP → 撒花庆祝 → 结算三个数字
```

一条关卡 = 一条攀岩线 = 6～10 个抓点，约 60～120 秒。

### 4.2 三大机制

**① 力度窗口抓点（核心 · Must）**
每个抓点有一个目标力度区间（绿区）。玩家把握力调进绿区并稳住约 0.3–0.5 秒即判定"抓住"，小人上移到该点。

**② 持续保持点 / sloper（核心 · Must）**
特定抓点是"需要稳住"的点：进入绿区后出现一个进度环，玩家需把力度**持续保持在窗口内 N 秒**，进度环填满才算过。力度一旦漂出窗口，进度回退。对应"持续注意力"。

**③ 节奏点（可选高难 · Could）**
高难路线播放背景音乐，某些抓点要求"踩着节拍"在正确时机进入绿区。命中节拍有额外分与视觉爆点。这是方案二的收编形态，做不完直接下线，不影响主线。

### 4.3 力度 → 动作 映射规则（判定表）

设归一化握力 `F`（0–100%），当前抓点绿区为 `[L, H]`。

| 输入情况 | 判定 | 小人表现 | 结果 |
|---|---|---|---|
| `F < L`（力太小） | 够不到 | 手伸出去够不着 / 单手吊着晃悠 | 不上升，可重试 |
| `L ≤ F ≤ H` 且稳住 | 干净抓住 | 顺畅发力、抓点、上移 | 上升到下一点，加"控制分" |
| `F > H`（力过猛） | 过度发力 | **ragdoll 甩飞 / 魔性旋转** | 脱手，回退或需重新抓点（传播点） |
| sloper：`F` 持续在窗口 | 保持成功 | 稳稳撑住，进度环填满 | 过点，加"稳定分" |
| sloper：`F` 中途漂出窗口 | 保持失败 | 手抖打滑、进度环回退 | 需重新稳住 |

**手感处理要点**：FSR 原始信号噪声大且非线性，务必做（a）开局个人化标定：让用户先"用力捏一次"取最大值，归一化到 0–100%；（b）滑动平均/低通滤波去抖；（c）屏幕侧显示握力条 + 高亮绿区，让"我现在多大力、离目标多远"一眼可见。

### 4.4 难度曲线

- 绿区变窄（更考验精细控制）
- 抓点更多、路线更长
- sloper 保持时间变长、数量变多
- 高难关叠加节奏点（可选）

## 5. 关卡与结算

**MVP 关卡**：1 面墙、1 条完整路线，含 5–7 个普通抓点 + 1–2 个 sloper，末尾 TOP 点。

**结算屏（Must）**：到顶后展示 3 个核心数字 + 1 句评价：
1. **完成用时**
2. **控制精度**：进窗口一次成功的抓点占比（%）
3. **最长稳定保持**：sloper 里力度不漂出窗口的最长时长（秒）

数据本地存 `localStorage` 即可，可选画一条"今天几次 session 的指力/精度小折线"。**不做云端看板**。

## 6. 视觉与反馈（性价比是关键）

**美术风格**：手绘卡通、粗描边、扁平色块，直接对齐参考图 6/7 的攀岩小人调性。用少量精致资产（1 个小人 + 1 组抓点 + 1 面墙背景）撑满画面，避免大量建模。

**画面构成**：
- 中央：攀岩小人 + 墙面 + 彩色抓点（下一个点高亮 + 目标力度环）
- 侧边：竖向握力条，绿区高亮，实时指针
- 顶部：TOP 目标标识

**Juice（让它"好看又好玩"的低成本手段）**：
- 干净抓点：粉笔白烟 puff + 轻微镜头上移 + "咔哒"音效
- 甩飞：**ragdoll 物理**（关节布娃娃）+ 镜头轻微抖动 + 滑稽音效 → 这是核心传播点，务必留
- 到顶：撒花 + 定格 + 三个数字弹出

**魔性动作实现**：用轻量 2D 物理（关节链/布娃娃）驱动小人四肢，过度发力时给一个扭矩让它旋转甩飞。视觉爆点主要靠这个，优先级高于任何数值系统。

## 7. 系统架构与技术选型

### 7.1 数据链路（极简版）

```
[捏握玩具：硅胶/3D打印外壳 + 1×FSR压力传感器]
        │  模拟电压 → ADC
        ▼
[ESP32-S3]  读取力度，归一化前的原始值
        │  WebSocket（Wi-Fi）或 Web Serial（USB）
        ▼
[浏览器 Web 游戏]  滤波 + 标定 → 力度 0–100% → 驱动攀岩逻辑与物理
        │
        ▼
[结算 + localStorage 本地记录]
```

现场只有无线 Wi-Fi（`ADVX-players` / `AdventureX`），**优先 WebSocket over Wi-Fi**；若现场网络不稳，USB + Web Serial 作为兜底（更稳、零依赖网络，演示更保险）。

### 7.2 软件技术栈（Web，低成本高视觉）

- **渲染**：HTML5 Canvas（2D）。可选 Phaser 或纯 Canvas + requestAnimationFrame。
- **物理/魔性**：Matter.js（做 ragdoll 甩飞与掉落）。
- **通信**：WebSocket 客户端 或 Web Serial API 读 ESP32。
- **音频**：Howler.js（音效）；节奏模式用 Web Audio 拿节拍时间。
- **部署**：Zeabur 一键部署（或本地起服务演示）。
- **提效**：可用 Qoder / CloudStudio 等 AI 编程环境快速出 demo。

> 引擎最终以"我能在 2.5 天做出高完成度"为准：默认 **Canvas + Matter.js**（上手最快、部署最轻、demo 一个链接就能跑）；若布娃娃调试顺手且时间充裕，可考虑 Phaser。不上 Unity（打包/联调偏重，与"最小成本最大视觉"目标冲突）。

### 7.3 硬件（最小依赖）

- **传感器**：1× FSR 薄膜压力传感器（自备，淘宝几块~几十块）。
- **MCU**：ESP32-S3（实验室可借），读 FSR + 无线/串口回传。
- **外壳**：硅胶灌模或 3D 打印的"豆豆板"造型，握感即卖点；MVP 阶段外壳可先用简易件，手感优化留后。
- **耗材**：面包板、杜邦线、电池。

**硬件同学的唯一硬指标**：ESP32 稳定输出一路平滑的力度值到浏览器。其余都是加分。

## 8. MVP 范围切分（MoSCoW）

**Must（必须，Demo 底线）**
- ESP32 + 1×FSR → 浏览器拿到实时力度值
- 开局个人化标定 + 滤波
- 握力条 UI + 绿区显示
- 力度窗口抓点：完整一条 5–7 点路线
- 至少 1 个 sloper 持续保持点
- 到顶庆祝 + 3 数字结算

**Should（应该，撑起"好玩/好看"）**
- ragdoll 甩飞魔性动作 + juice（烟尘/抖屏/音效）
- localStorage 记录 + 小折线
- 难度递增的第 2 条路线

**Could（可选，加分/彩蛋）**
- 节奏高难模式（方案二收编）
- 语音鼓励（TEN / MiniMax）
- 更精致的外壳与握感

**Won't（本版不做）**
- 摄像头走神检测 / 姿态识别
- 云端数据看板（飞书多维表格）
- AR（Rokid / XR Hand）
- 多人 / 账号 / 大地图

### Demo 脚本（1 分钟闭环）
1. 拿起玩具，用力捏一次完成标定（10 秒）。
2. 开始爬：连续几个抓点，展示"力度刚好=干净上升"。
3. 故意用力过猛 → 小人魔性甩飞（观众笑点/截图点）。
4. 遇到 sloper：稳住力度、进度环填满、过点（讲"持续注意力"故事）。
5. 到顶撒花 → 结算三个数字 → 一句"这既练了指力，也练了专注"。

## 9. 分工与时间线（约 2.5 天）

**软件（你）**
- D1 上午：搭 Canvas 场景 + 假数据（键盘/鼠标模拟力度）跑通抓点逻辑
- D1 下午：握力条 UI + 力度窗口判定 + 一条路线
- D2 上午：sloper 持续保持 + 结算屏 + 美术资产接入
- D2 下午：接真实 ESP32 数据、标定与滤波联调
- D2 晚 / D3 上午：ragdoll 魔性动作 + juice + 打磨手感
- D3：兜底、录 demo、（有余力）节奏模式

**硬件同学**
- D1：采购/借用 FSR + ESP32，面包板接通读到模拟值
- D1 晚：ESP32 无线/串口把力度值推到浏览器（先能连上就行）
- D2：外壳（3D 打印/硅胶）+ 装配 + 稳定性
- D2 下午起：与软件联调标定、滤波、延迟

**关键同步点**：D1 结束前定死**通信协议与数据格式**（比如每 20ms 推一个 `{force: 0-4095}` 的整数），软硬件才能各自并行。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| FSR 信号抖/漂 | 手感差、判定飘 | 软件端滤波 + 死区 + 个人化标定；判定用窗口而非精确值 |
| 现场 Wi-Fi 不稳 | 数据断流 | 优先/兜底用 USB + Web Serial |
| 硬件联调拖到最后 | 软件没数据可调 | 全程用键鼠/滑块模拟力度开发，最后 1 段才接真硬件 |
| ragdoll 调试耗时 | 传播点没做出来 | 先做"能玩"的简版甩飞，juice 属 Should，不阻塞 Must |
| 节奏模式吃时间 | 主线延误 | 明确列 Could，主线锁死前不碰 |

## 11. 未来扩展（讲愿景用，本版不做）

- **摄像头走神检测**：Apple Vision 手部/姿态 + 端侧推理，检测"手离开玩具/看别处"作为走神信号，触发游戏内打滑——把 handoff 完整 AI 链路补上。
- **云端数据看板**：飞书多维表格，跨天的专注时长 / 指力曲线。
- **语音陪练**：TEN / MiniMax 做"会说话、会鼓励的玩具"。
- **AR 指力可视化**：Rokid Glasses + XR Hand。
- **节奏玩法深化**：整套 beatmap 编辑与曲库（方案二独立成模式）。
