# FocusGrip「指哪爬哪」· 技术栈

FocusGrip 的核心 AI 挑战是一个边缘端多模态时序融合问题：如何在浏览器端实时融合视觉、触觉、行为与自报四类异构信号，在信号稀疏、噪声大且极度保护隐私的约束下，准确判断用户注意力状态并生成个性化干预。

---

## 一、多模态边缘 AI 融合引擎（核心）

系统同时接入六类信号源：面部关键点（MediaPipe Face Landmarker，468 点，~30fps）、手部关键点（Hand Landmarker，21 点×2 手，~30fps）、姿态关键点（Pose Landmarker，33 点，~30fps）、压力传感器（FSR + ESP32-S3，50Hz）、桌面行为（鼠标空闲 + 活跃窗口标题，轮询）以及用户主动标记（按需触发）。所有视觉推理通过 WebAssembly 在浏览器 CPU 本地执行，视频帧不离开浏览器进程。

融合管线分三步。**语义特征提取**：各通道不传原始数据——面部通道计算眨眼速率、张嘴速度与头部晃动角速度，手部通道计算手腕位移幅值与关节移动方差，姿态通道计算躯干晃动幅度，三个视觉通道各自输出归一化"节律分数"（0–100），压力通道输出均值、方差与超阈值事件计数。**个性化基线建模**：每次摄像头开启后，前约 90 帧（约 3 秒）静默建立各通道的均值 μ 与标准差 σ，后续帧以 Z-score 计算偏离度。基线仅存在于当前会话内存，跨会话不存储，兼顾个性化与匿名性。**交叉验证融合判定**：单通道超基线可能是噪声（如打喷嚏），系统仅当两个及以上通道同时高于自身基线时触发"多通道变化"提示——这是一种无监督的跨模态共现异常检测，不依赖标注数据。融合判定优先级为用户主动标记 > 多通道变化 > 单通道持续偏离 > 周期性提示。端到端延迟控制在 100ms 以内。

## 二、LLM 干预生成与多终端分发

融合引擎判定需干预后，系统将结构化状态快照（压力统计、各通道节律分数与基线偏离度、多通道变化分数、用户标记状态——仅抽象数值，不包含任何图像或坐标）通过本地 Next Route Handler 代理发送至小米 MiMo Chat Completions API（mimo-v2.5-pro）生成非诊断式温和建议。MiMo 不可用时自动降级为本地兜底建议库。API Key 仅存于 `.env.local`，前端零敏感信息暴露。

干预信息双路径分发：像素心流网页中的上浮建议气泡，以及桌面 MindReset Quote/0 电子墨水屏（296×152）。墨水屏的选择是交互设计决策——低刷新率纸质质感天然不打扰。本地 Node.js 桥接进程每 60 秒轮询建议接口，内容指纹去重，仅在变化时通过 Dot. Text API 推送。

桌面行为监测模块独立运行：检测鼠标空闲超 10 分钟或 YouTube、哔哩哔哩、微信等应用前台超 10 分钟时，弹出攀岩关卡弹窗，在分心趋势刚形成时主动"截胡"，引导用户进入指力微练习。

---

## 三、指力攀岩游戏引擎

游戏承担 AI 体系的"行动转化"职能——ADHD 注意力训练目标被内化为玩法机制。自研 Verlet 积分 + IK 长度约束物理求解器，按 7.5 头身人体比例建模，肩/髋双质点承载重量，四肢通过长度约束实时解算攀岩姿势，每帧 16 次约束迭代。力度窗口抓点训练冲动控制（精准控力），持续保持点 sloper 训练持续注意力（稳态维持），短关卡（60–120s）适配 ADHD 注意力跨度。渲染层 HTML5 Canvas 单文件架构 + Matter.js ragdoll 效果 + Howler.js 音频。

---

## 四、硬件与数据链路

指力训练板：硅胶/3D 打印外壳 + FSR 薄膜压力传感器 + ESP32-S3。ES32 以 50Hz 通过 Wi-Fi（WebSocket）或 USB（Web Serial）推送力度值至浏览器，软件端滑动平均滤波 + 开局个人化标定后归一化至 0–100%。同一路传感器信号同时驱动攀岩游戏判定与多模态融合的触觉通道输入。

---

## 五、隐私架构

全本地推理（视频帧不出浏览器）、抽象数值传输（MiMo 不接触原始数据）、会话级匿名基线（跨会话不存储）、用户可控开关（可随时关闭任意 AI 模块）、非诊断式引导（不贴标签不替代医疗）。
